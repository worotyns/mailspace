# MS-009: Team workspace i shared mailbox

Etap: M3 · Priorytet: P1 · Zależności: 001,006 · Status: organization + grant foundation implemented; team read enforcement and send-as planned

## Zakres

Role owner/member, osobiste konta vs wspólne, send-as osobno, audit bez treści.

## Kryteria odbioru

Deny-by-default dla private accounts; permissions na jobs/live events/attachment; usunięcie membership natychmiast odbiera sesji dostęp.

## Definition of done

Kod, testy zachowania i błędów, brak wycieku między kontami, dokumentacja/capabilities zgodne z funkcją, mały reviewable commit. Sprawdź AGENTS.md; nie implementuj sąsiednich issue przy okazji.

## Foundation delivered early

Profile/timezone, organizations, owner/member roster, active context, add/remove existing local users and metadata audit are implemented per user UI feedback. Membership never grants private mail access. Shared mailbox/send-as remain planned; OpenPGP dependency still applies to the secure shared-mail stage. ADR 0011 / SPACES.md.


## Source-grant foundation (ADR-0045, schema 14)

Explicit `source_grants(workspace_id, account_id, mailbox, grantor_id, grantee_id, can_download)` are stored per organization. Only the current account owner may grant; the grantee must be a provisioned user and current member; self-grants are rejected; an unknown organization, account or user fails closed. Every authorization call rechecks current ownership and both memberships, so revocation and membership removal block the next read immediately. `can_download` is stored but not enforced yet. No HTTP endpoint, UI, job, model call or personal read uses a grant yet: this slice is the reviewed foundation, and no member gains private-mail access from it. Enforcement is the next slice with two-user denial tests for every widened path; separate send-as remains distinct.


## Read-only team enforcement (ADR-0045)

The timeline resolves a viewer to owned accounts plus currently valid grants, so a grantee sees shared cached mail in All activity/Unread (excluded from Unsorted triage) with a `shared by` badge and no reply, archive, label, Space, read-state or assignment controls. `/api/messages/raw` and attachments require `can_download`; without it only cached preview text is readable. Every mutation still uses owner-scoped calls and returns 404 for a grantee, and rules/decisions/bulk/jobs never see granted mail. Two-user tests cover each path plus folder scope, outbox exclusion, revocation and membership-removal blocking. An owner-only `/sharing` settings panel lists, creates and revokes grants with CSRF/Origin checks and never reveals another user's grants or whether an email is provisioned. Remaining: per-user team state (MS-010) and separate send-as.
