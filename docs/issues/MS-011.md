# MS-011: Attachment Drive

Etap: M4 · Priorytet: P2 · Zależności: 008,010 · Status: virtual view implemented (ADR-0048); optional cache/download endpoint planned

## Zakres

Wirtualny widok IMAP attachment refs, później opt-in cache/preview.

## Kryteria odbioru

Dane usuwane po revoke; encrypted filenames/bytes lokalnie po decrypt; brak background OCR; limity i preview isolation.

## Definition of done

Kod, testy zachowania i błędów, brak wycieku między kontami, dokumentacja/capabilities zgodne z funkcją, mały reviewable commit. Sprawdź AGENTS.md; nie implementuj sąsiednich issue przy okazji.

## Virtual attachment view (ADR-0048)

A cross-message `/attachments` page lists attachment references already parsed into cached previews: name, media type, subject, sender, account, time and a link to the message reader. Bytes stay in the cached original MIME and are read locally in the reader with its preview isolation; nothing is copied, uploaded or indexed, and there is no background OCR. Encrypted attachments are not listed because the parser cannot see them. Limits: 64 accounts, 500 messages, 1000 references, 200 displayed rows. Team scope: only owned accounts plus grants with `can_download`; revocation removes the rows immediately. Remaining: an optional opt-in local attachment cache and a dedicated byte/preview endpoint, with purge-on-disable semantics.
