# MS-018: Full-history synchronization and native IDLE optimization

Etap: M1 follow-up · Priorytet: P1 · Zależności: 003 · Status: planned

## Zakres

Replace the explicitly bounded latest-500 recent-mail window with user-controlled older-history pagination and cache retention/eviction. Add capability-driven IDLE/reconnect while preserving polling fallback. Expose progress, last success and bounded sanitized error states, without message data in logs.

## Kryteria odbioru

Large mailbox, concurrent EXPUNGE/new mail, UIDVALIDITY changes, multiple accounts, offline restart and cancellation. No duplicates, stale-generation writes or remote flag changes. Storage limits and incomplete history remain visible. Native IDLE never becomes required for a working mailbox.
