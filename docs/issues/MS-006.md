# MS-006: OpenPGP/MIME i bezpieczny composer

Etap: M2 · Priorytet: P0 · Zależności: 004,005 · Status: in progress

## Zakres

Decrypt/verify i encrypt/sign w browser; recipient trust, missing key, drafts, quotes, attachments.

## Kryteria odbioru

GnuPG/Thunderbird round-trip; canonicalization; corrupted sig; mixed recipients; ciphertext drafts; brak plaintext w API/DB/logs/trace; brak cichego downgrade.

## Definition of done

Kod, testy zachowania i błędów, brak wycieku między kontami, dokumentacja/capabilities zgodne z funkcją, mały reviewable commit. Sprawdź AGENTS.md; nie implementuj sąsiednich issue przy okazji.

## Integrated alpha slice

Browser signed encryption, explicit all-recipient trust, own Sent copy, wildcard Bcc key IDs, opaque MIME submission/outbox, local decryption/embedded-signature verification and local attachment downloads work in the current slice (ADR-0013). GnuPG, two-user HTTP/SMTP/Sent integration and a synthetic browser round-trip are covered. Full issue remains open: detached signatures, binary/legacy layout compatibility, secure quotes and Thunderbird matrix. Local drafts/attachments are now implemented in ADR-0014.

Local ciphertext drafts (explicit save/load, no autosave/IMAP sync) and encrypted attachments (10 files / 1 MiB total) are implemented in the next slice, ADR-0014. Remaining: detached-signature read/send, binary/legacy variants, secure quote UX and Thunderbird matrix.

## Current completion and next implementation slice

Binary input and exact-octet detached signature reading are implemented (ADR-0023/0024). Local detached signing is implemented (ADR-0028), as are memory-only worker sessions and inline local decrypt/autopreview (ADR-0032). These do not implement signed-only HTTP sending. Folded display quotes are not automatic quoting/forwarding of decrypted content.

Next: explicit authored signed-only mail in the full composer, with a follow-up ADR before opening a transport endpoint. Reuse the existing local signing and multipart/signed formatter. Require visible unencrypted-send consent, reject mixed ordinary/encrypted/signed bodies and unsigned client envelope headers, preserve exact inner MIME bytes, and keep the server's original authoritative From/To/Subject handling. Do not change generic decrypted export policy, silently quote decrypted content, or allow an encrypted-parent downgrade. Reply support needs the same current-source transaction and original-reference gates as ordinary/encrypted sending; it must not be inferred from the new-message case.

Acceptance must include application → HTTP → durable outbox → synthetic SMTP/Sent → GnuPG verification with Unicode and binary attachments, tamper rejection, owner/CSRF denial, sender binding/lock/expiry and SMTP unknown-result behavior. Structural server MIME validation is not signature or trusted-sender verification. Real Thunderbird round-trip remains a separate external-client gate.


### Authored signed transport slice (ADR-0037)

The dedicated signed-only HTTP endpoint and bounded canonical MIME validator are implemented. Exact application-generated Unicode/binary-attachment MIME survives durable outbox, synthetic SMTP and Sent; GnuPG verifies it and rejects tampering. Tests cover explicit consent/authored provenance, unknown fields, ownership/CSRF, encrypted-parent refusal, stale-source transactions, legacy nonce hashes and unknown SMTP outcomes without resending. No server signature/trust verification is claimed.

The next slice remains the visible full-composer signing-only action with explicit unencrypted-send consent and client egress/lifecycle tests. No decrypted source or automatic quote is permitted. Real Thunderbird acceptance and broader MS-006/1.0 gates remain open; the earlier transport-planning paragraph is superseded only for the implemented endpoint.
