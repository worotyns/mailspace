# ADR 0010: Durable send certainty, MIME and Sent copies

Status: accepted · 2026-11-12.

## Decisions

Migration v4 adds an owner-scoped outbox. Composing ordinary plaintext requires explicit per-message consent. No background draft autosave, automatic quoting, attachments or silent encryption fallback. Replies to encrypted cached messages are refused by the ordinary composer. Browser OpenPGP is the next core stage, not claimed as implemented here.

The sender address is the verified account address, not an arbitrary form field. Recipients are parsed/bounded; initial envelope support is ASCII addresses with encoded Unicode display names. MIME uses UTF-8 text/plain, quoted-printable, CRLF, generated Message-ID, Date and validated threading headers. Bcc recipients appear only in private envelope metadata, never the SMTP MIME or Sent copy. Subject/address header injection and oversized input are rejected. Signed/encrypted raw MIME submission will require a separate client boundary.

A random compose request id and account-scoped unique constraint make repeated identical submissions resolve to one record. Changed content with the same request id fails. pending→sending is a database compare-and-swap before any SMTP operation; only that transition can call SMTP. Account revision changes reject prepared messages from an obsolete configuration. All read/write/list/dispatch access checks the account owner. The outbox is bounded to 500 records / 64 MiB original MIME per account.

There is no automatic retry or exactly-once delivery claim. Before DATA, connection/auth/envelope failures are not accepted. After DATA starts, connection loss or missing final acknowledgement is unknown; an explicit SMTP 4xx/5xx rejection is rejected. A final successful response is accepted by the SMTP server, not proof of recipient delivery. Error strings from the remote server are never logged or displayed. Interrupted sending operations recover as unknown on startup, not pending. Subsequent submit/refresh never resends accepted/rejected/unknown records.

Once SMTP acceptance is durable, the app attempts one IMAP APPEND into the configured exact Sent folder (default Sent), with Seen set only on the new outgoing copy. No folder is auto-created. Failed or lost APPEND acknowledgement leaves the SMTP message accepted and copy status unknown. Never resend SMTP to repair a Sent copy. Some providers automatically save sent mail too; configuring the exact folder does not deduplicate provider-side copies. This limitation is visible in the operator guide.

The request budget is 20 seconds SMTP, 12 seconds Sent copy plus short durable state writes. The HTTP write/shutdown budget is 45 seconds. Result persistence has a bounded context independent of browser disconnect. Startup recovery is for a single app instance; multiple active web processes against one SQLite installation are unsupported. There is no outgoing retry worker.

## Privacy and rollback

Ordinary outgoing MIME, envelope recipients (including Bcc) and subject are sensitive server-side data, retained under the owner account. This is not the browser OpenPGP vault and does not encrypt ordinary mail at rest. No model, index, telemetry or webhook is involved. Offline backup/restore includes this table and the credential keyring. Schema rollback requires a complete offline backup; old binaries refuse v4. Restoring a backup must never turn unknown records into a retry queue.

## Validation

Tests cover concurrent duplicate dispatch, nonce replay/content conflict, two owners, old configuration generation, unknown SMTP and APPEND results, crash recovery, Bcc, Unicode/CRLF MIME, header injection, explicit unencrypted consent and encrypted-reply rejection. Scripted verified TLS/STARTTLS SMTP peers exercise acceptance/rejection/connection loss/timeout; full integration sends only to the isolated .test SMTP sink and checks one Sent APPEND.
