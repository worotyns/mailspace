# ADR-0048: Virtual attachment view over cached mail

Status: accepted for MS-011.

MS-011 describes an attachment Drive as a virtual view of IMAP attachment references with an optional cache later. This slice implements the virtual view: a cross-message list of attachments already described by cached previews. It adds no storage, no upload, no object store and no OAuth provider; attachment bytes stay in the cached original MIME.

## Data and limits

`Preview.Attachments` (name up to 180 bytes, media type up to 100 bytes) is already parsed with the message and bounded by the existing MIME part cap. `AttachmentList` reads only that metadata, newest message first, for the caller-authorized account ids: at most 64 accounts, 500 cached messages scanned and 1000 attachment references returned. The page displays at most 200 rows per view (the matching count is still shown). A structurally invalid cached attachment array is skipped, never fatal.

Encrypted mail is opaque to the parser and carries no parsed attachments, so its attachment names and bytes never appear here. They stay a client-decrypt-only concern. No filename, byte, preview or derived text is copied, uploaded or added to any index, and there is no background OCR or preview rendering on the server.

## Access and team scope

The owner sees attachments from their own cached accounts. A teammate sees an attachment only when the grant for that account enables `can_download`; a preview-only grant is omitted entirely because the Drive is about obtaining bytes. Every row links to the existing `/messages/read` reader, which enforces the same grant and then reads the original message locally with the established preview isolation. Revoking a grant removes the rows immediately, leaving no copied data behind. The filter is a bounded case-insensitive match over cached metadata only.

## User experience

The page lives with the other list panels, states that bytes are read in the message reader and that encrypted attachments are not listed, supports a name/type/subject/sender filter with a match count, and distinguishes "no cached attachments yet" from "no matches". It is metadata-first and honest: it never promises a file server, synchronization or a preview it cannot deliver locally.

## Rollback

This slice adds no schema, route data or storage: removing the page and route returns the installation to the previous state with cached mail unchanged. No migration or backup is required.
