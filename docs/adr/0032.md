# ADR-0032: Memory-only crypto session worker

Status: accepted. Extends ADR-0012/0013 for explicitly unlocked browser memory. No new key/plaintext upload permission.

A fixed same-origin module SharedWorker holds the existing LocalVault instance, using its existing OpenPGP implementation and protected IndexedDB key records. Unsupported SharedWorker construction falls back to a dedicated module worker; browsers without workers, or whose policy denies both worker constructors, retain the page-local vault. A passive document keeper port prevents last-port gaps during same-document component replacement; it sends no key operation or activity touch and disconnects on pagehide. Import, export, generation and trust editing remain on the local key page and are not exposed through RPC.

The client factory provides metadata listing, explicit unlock, signed encryption, detached signing/verification and decryption. Public detached-signature verification works while the private key is locked. Ordinary recipient/format errors report the truthful owned vault state rather than pretending that a healthy key was locked. Narrow, size-checked messages carry operation arguments only over a local MessagePort. No arbitrary method invocation, fetch URL, callback, script or private-key export operation exists. At most 16 operations queue. Passphrases are not stored after unlock and unlocked private keys never leave the vault's private fields or enter storage. Decrypted results retain client-decrypted provenance and are returned only to the requesting authenticated port.

Before and after every operation, including activity touch, the worker requests only GET /api/crypto/session with the existing same-origin cookie, no request body and no operation arguments. This protected no-store endpoint returns current user id, session expiry and a SHA-256 binding of the random session cookie, never the cookie or CSRF token. The binding is not an authorization credential. Each port pins its user and binding; logout/revocation, a new login for the same user, another user, missing authentication or a changed binding denies the result and locks memory. A post-operation authentication check prevents plaintext return after an in-flight session change.

The worker document has its own CSP: script-src self, connect-src restricted to the fixed origin/api/crypto/session path for hostname origins and 127.0.0.1. Other literal IP origins use connect-src self because CSP host-source matching does not support these IP literals; worker code still admits only the fixed metadata GET, never RPC arguments, and all cross-origin egress remains denied. See [CSP source matching](https://www.w3.org/TR/CSP/#match-url-to-source-expression), worker-src none and default-src none. Embedding pages allow worker-src self; the local keys page keeps connect-src none. This is ordinary CSP, without volatile connection-allowlists APIs. Same-origin application code remains trusted: this worker is not an XSS isolation boundary. Untrusted mail HTML remains in the separate opaque scriptless sandbox.

Idle timeout is five minutes, bounded by the login session's expiry. Real user activity may send an authenticated argument-free touch no more often than once per 15 seconds; a passive timer must not keep the key alive. Touch cannot unlock an expired key. Explicit lock immediately invalidates client promises, bypasses the operation queue, increments worker/vault epochs and broadcasts locked state. Even a fresh unbound same-origin port may lock retained memory: this denies access, returns no active-session metadata and grants no privilege. A late queued response cannot restore the client's unlocked state. Remote revocation is detected on the next operation; there is no continuous authentication poll. Closing a client disconnects only, allowing another same-session view to continue. Dedicated-worker disposal terminates that page's worker.

The browser controls worker lifetime. SharedWorker construction requests the optional extendedLifetime hint to improve navigation/reload reuse; browsers may ignore it and it grants no persistence guarantee. Shared ports can reuse an unlock while the browser keeps the worker alive, but F5/navigation, closing all pages, memory pressure, browser restart or unsupported shared workers can require the passphrase again. No service worker, persistent plaintext key cache or sessionStorage/localStorage passphrase workaround is introduced. Lock drops JavaScript references; physical RAM erasure cannot be guaranteed. Source and compatibility: MDN [SharedWorker constructor](https://developer.mozilla.org/en-US/docs/Web/API/SharedWorker/SharedWorker) and [worker lifetime](https://developer.mozilla.org/en-US/docs/Web/API/Web_Workers_API/Using_web_workers#shared_worker_lifetime).

No database migration or new compulsory service is needed. Rollback to page-local crypto removes this worker and its client integration; persisted private keys remain protected in the unchanged local vault format. Boundary tests cover multi-port reuse/disconnect, same-user login rotation, cross-owner denial, expiry, lock during decryption, late client responses and post-operation revocation. Existing crypto and no-egress tests remain mandatory.


Compatibility feedback: the unlock dialog opens before metadata RPCs. Asynchronous worker loading errors mark the client unavailable and reject current/future calls immediately, rather than retaining a dead port until every timeout. Listing/activity RPCs have an eight-second deadline; signing/encryption keep the existing sixty-second deadline. Neither an unavailable worker nor rejected authentication triggers an automatic page-vault downgrade or plaintext send. This is a fail-closed UI/lifecycle correction, not a new export or persistence boundary.


### Startup-only SharedWorker recovery

A browser can expose SharedWorker yet fail to load its module asynchronously. A single recovery to a fresh dedicated module worker is permitted only on that shared transport's startup `error`, before any message (including unknown/state/error responses) and before any non-list operation has been dispatched. Pending operations must all be argument-free key metadata listings. Only their IDs and empty list requests are replayed, with their original deadlines; private arguments are never retained for retry. This is not a send retry.

The replacement uses the same fixed worker entrypoint and authenticated kernel, including server session/user/binding checks before and after operations. It starts with a locked vault. Authentication rejection, RPC errors, messageerror, timeout, explicit lock/close, any completed startup or any private-operation attempt never triggers recovery. Dedicated construction failure stays unavailable; this path cannot call the page-local factory fallback. Old listeners are removed and transport generations invalidated; stale messages/errors cannot restore key state or affect the replacement. Keeper retirement uses captured entry identity so an old client cannot retire a newer document keeper. Recovery is attempted at most once, with truthful dedicated session mode and no reload-lifetime promise.

Regressions cover the one metadata replay, stale worker messages/errors/deadlines, authentication refusal, private-operation blocking, no page-vault fallback, lock/messageerror, constructor denial and overlapping keeper generations. This does not substitute for native Safari acceptance.
