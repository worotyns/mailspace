# ADR 0007: Local identity, SQLite and opaque server-side sessions

Status: accepted · 2026-11-12.

## Decision

Users provisioned by CLI, without public registration. Passwords hashed by alexedwards/argon2id (MIT), Argon2id 64 MiB, 3 iterations, parallelism 2, 16-byte random salt and 32-byte key. modernc.org/sqlite (BSD-3-Clause) provides CGO-free persistence. No application secrets or OpenPGP keys enter this schema.

SQLite v1 migration creates users, account ownership metadata and sessions. WAL, foreign keys and busy timeout apply on each connection through a constructed URI; config accepts a filesystem path, not arbitrary DSN parameters. DB file mode 0600, new parent directory 0700. Newer schema versions are rejected. Initial migrations are forward-only; rollback requires an offline backup (docs/IDENTITY.md).

Sessions: random 256-bit opaque cookie, only SHA256 token digest stored; 8-hour fixed TTL; random per-session CSRF token. HttpOnly, SameSite=Strict, Path=/, no Domain, Secure and __Host- prefix in HTTPS. Explicit loopback-only HTTP development uses a separate cookie name. Login rotates an existing session; logout and per-user revoke-all persist across restarts.

Exact configured Origin for all login/logout mutations; synchronizer CSRF token additionally required for logout mutations. Password verification runs for unknown users against a dummy Argon2 hash. Bounded rate-limit state (4096 IP entries, ten attempts per minute) and two concurrent login hashes. X-Forwarded-For is deliberately not trusted. Reverse-proxy installations currently share the proxy IP bucket; explicit trusted proxy support is future work.

## Scope and consequences

Personal mode is opt-in, distinct from the synthetic demo. Ownership queries filter by account id AND owner id; not-found does not disclose another user's account. Only account metadata exists yet; IMAP credentials/transport are MS-002 onwards. Shared-team ACL, reset/MFA/invitations and idle-timeout policy are future stages. Browser crypto keys/passphrases are never stored or used for login.

Personal auth pages use Referrer-Policy: same-origin, keeping external referrers suppressed while preserving Origin for native form POSTs. Demo remains no-referrer. Never accept Origin:null as a workaround; reject it. Rationale: https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Referrer-Policy#effect_on_the_origin_header
