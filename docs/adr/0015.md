# ADR 0015: Text-first MIME and explicit isolated HTML preview

Status: accepted · 2026-11-13. User direction: native text, HTML conversion, optional popup preview. MS-008 is in progress.

## Default presentation

Prefer a native text/plain MIME alternative. For HTML-only mail, extract inert bounded text; do not display markup in the conversation. Go uses golang.org/x/net/html 0.62.0 (BSD-3-Clause) for ordinary cached previews, dropping active/document-head content and preserving readable paragraph/table structure. Bounds: 64 KiB decoded HTML, 96 traversal depth, 10,000 nodes, existing MIME/raw/cache limits. Any encrypted sibling or inline PGP marker still makes the entire server preview opaque. Original MIME remains unchanged. Existing cached previews are not a content index; a future preview-version rebuild can refresh older cached placeholders. The local full-text reader already converts their original MIME on explicit open.

In the browser, native text is likewise preferred; HTML-only fallback uses the pinned postal-mime text conversion, then textContent. For encrypted mail, MIME parsing, conversion, HTML sanitization and viewing all occur after local decryption. Go receives none of that decrypted HTML or text. Ordinary mail has an owner-scoped local full-text/attachment reader without requiring a private key or a key-vault database.

## Preview boundary

Preview HTML opens a native dialog, not an automatic message render or external popup. DOMPurify 3.4.17 (Apache-2.0 option) sanitizes up to 256 KiB to a strict formatting/tag/attribute allowlist. Scripts, forms, frames, images/media, SVG/MathML, author CSS, resource attributes, ids/names, handlers and navigation hrefs are removed. Thus even the preview has no remote images or active links in this first implementation. It is a simplified structural view, not pixel-identical sender CSS. CID images/remote-resource opt-in are not silently enabled.

The only HTML sink is a dynamically created iframe.srcdoc, with sandbox="" (no allow-scripts, allow-same-origin, forms, popups or top navigation) and no-referrer. This is a narrow reviewed exception to the general ban on decrypted attributes: the sanitized source document is client-owned inside hx-disable/history-disabled UI, never a hidden field, data attribute, server template or HTMX payload. No mail HTML is inserted into the application DOM with innerHTML/template.HTML. The child document's CSP denies scripts, connections, images, media, fonts, frames, objects, forms and base URLs. The parent remains unframeable, allows only local source frames, denies images, and permits one exact SHA-256 hash for a fixed application stylesheet. The hash is computed from the build output also used by the renderer; it does not authorize mail-supplied inline styles.

Close/Escape removes the frame/document. Lock/hidden tab/departure/expiry also discard the decrypted HTML reference, clear text and close/remove any preview. No preview POST, backend HTML rendering service, AI, content index, webhook or telemetry. Local storage does not persist decrypted HTML. Original mail can be downloaded explicitly as an octet-stream attachment.

## Validation and compatibility

Go and browser tests cover native-text preference, HTML-only Unicode/entity conversion, encrypted siblings, bounds and malicious MIME/HTML. A jsdom 31.0.1 dev-only corpus checks removal of active/resource/navigation markup; Node >=24.15 is required for these tests (the container's Node 24.22.3 was checked). The class test checks empty sandbox/local source and document removal. Real browser tests use ordinary and encrypted HTML with a local request-counting probe for script/image/CSS/frame/form/link/refresh traps; visible preview/text make zero probe requests, including after local decryption. Two-user access checks reuse the authorized raw MIME route. This is functional/security regression coverage, not an independent sanitizer audit.

The encrypted reader still distinguishes signature validity from trust. Detached-signature/binary legacy OpenPGP and Thunderbird compatibility remain separate MS-006 gates. A future HTML/CID resource change requires another reviewed boundary, not widening this allowlist casually.
