# ADR-0038: Explicit local original-message quotes

Status: accepted. Extends ADR-0014/0037 for the full browser composer; no decrypted export permission.

The full composer can explicitly quote the selected cached IMAP original. The action makes only the existing authenticated raw-message GET with the current account/folder/UID/UIDVALIDITY. It never chooses a message by subject or a previous Space entry. Restored draft locators replace the page's initial locator for this operation. No quote is fetched, decrypted or inserted automatically. Missing/stale/foreign originals fail through the existing raw-source authorization boundary.

MIME parsing/decryption/verification and HTML-only-to-inert-text conversion stay in browser crypto modules. Only the bounded text body (maximum 32 KiB UTF-8) is quoted, never attachments, HTML markup or original headers. Each line receives a literal `> ` prefix. An oversized quote is refused, not silently truncated. Known-invalid signatures are refused; unsigned, unknown-key and valid-but-untrusted states remain visibly distinct. A valid signature never implies sender trust. Loading a reply draft displays that the original signature has not been rechecked in the current session. Mailspace's existing bounded MIME/decompression limits apply.

The composer assigns quote text only to its unnamed client-owned textarea inside hx-disable. Decrypted quote text never appears in attributes, generic events, hidden inputs, HTMX, backend templates, storage or diagnostics. A quote from encrypted MIME makes encryption mandatory for the current draft, revokes plaintext consent and disables signing-only. The server independently rejects unencrypted replies to encrypted originals. The full encrypted MIME, including quoted text, can leave the browser only through the existing explicitly triggered encrypted-send contract. Ordinary cached text may be quoted into an authored signed-only draft after its separate readable-content consent; decrypted quotes may not. There is no generic decrypted-message submission or automatic quote/forward source for signed-only mail.

Lock/hide/expiry/navigation clear quote text and pending work. No late response may reinsert text. Repeated action during loading is suppressed; an applied quote is not inserted a second time in the same editing session. Loading another draft replaces the current source and body instead of mixing source contexts. All send nonce/outcome rules remain unchanged.

## Encrypted local draft format

New drafts use authenticated encrypted payload version 2, adding a required boolean encryptionRequired inside ciphertext. No new plaintext IndexedDB column, server schema or metadata is added. This flag follows an encrypted original/decrypted quote through explicit save/load and cannot be cleared just by editing quoted text. Version 1 remains readable; a legacy reply draft conservatively requires encryption because its original protection was not recorded. Legacy new-message drafts default to authored mode. Unknown versions, missing/non-boolean version-2 flags and malformed locators fail closed.

A self-draft signature must match the unlocked personal key as well as the saved fingerprint. The fingerprint in the unencrypted record is not authority: a valid third-party signature plus edited record metadata cannot impersonate an authored self-draft or clear its protection requirement. The old personal key must be unlocked to recover its saved draft; an imported correspondent key does not authorize a draft.

No background migration or overwrite is performed. Existing version-1 ciphertext is upgraded only on explicit Save. Rollback binaries supporting only version 1 cannot read new version-2 drafts: retain the browser database and return to a version-2-capable build to recover them. The protected key and encrypted draft copies must be preserved separately from server backup. No plaintext migration or new recovery promise is introduced.

Regressions must cover encrypted/ordinary/HTML-only quotes, Unicode, exact source metadata, signature states, size bounds, no attachment copying, no plaintext/key/passphrase egress, draft-version compatibility, mandatory encryption after restore and lock during a pending request. Manual browser/external-client acceptance is recorded separately, not inferred from tests.
