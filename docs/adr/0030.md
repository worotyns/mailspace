# ADR-0030: Compact mail controls, trusted application panels and status labels

Status: accepted. Supersedes ADR-0029 only for the visible label UI and application-document embedding.

## Product behavior

Spaces remain message-level many-to-many views. Restore the existing private label records as optional status metadata: manage names/colors in Settings, filter the same timeline, and add/remove on one message, an original cached thread or mail with a person. Labels never appear as another sidebar taxonomy. Label edits must not increment the Space manual-override epoch. Space edits and local archive continue to protect manual decisions from late model results.

A compact horizontal message toolbar keeps reply, thread, local reader/attachments, Space memberships, labels, Jev confidence and local archive reachable. It scrolls within the message on narrow screens. The displayed confidence remains the overall decision score, not an invented probability for each Space. Native details folds consecutive quoted lines; inline replies between quotes remain visible and the original MIME is unchanged.

## Trusted panels

Own Settings/Keys/Accounts/Rules/Labels/Automation/Profile/Organizations/Compose/Reader/Outbox/archive-preview documents may open in a same-origin application iframe inside a native modal. Only authenticated allowlisted application paths requested with Sec-Fetch-Dest: iframe change frame-ancestors from none to self, with X-Frame-Options SAMEORIGIN. Other CSP directives are preserved, including the key page's connect-src none. Top-level documents retain their existing framing protection. A forged fetch header is not authorization; all handlers still check sessions, ownership and mutation CSRF.

These application frames are fully trusted same-origin documents. This does not apply to email HTML: its existing sanitized opaque sandbox still has no scripts, same-origin access or external resources. Messages between panel and parent contain only navigation, dirty-state booleans, command requests and send outcome metadata. The parent checks both exact frame window and origin. No key, passphrase, plaintext body or decrypted MIME is sent through this channel. Closing the panel locks its local vault and removes the document. A dirty full composer requires explicit discard before closing.

## Bulk changes and limits

Local archive and label operations preview at most 500 owned cached messages per pass. The POST recomputes and compares a selection hash, then revalidates every source/account revision and UIDVALIDITY in a bounded transaction. A foreign, stale or capacity failure rolls back the complete metadata change. Archive does not delete mail or move provider folders. People counts use active incoming cached mail.

Decision acceptance uses up to 50 selected/displayed saved proposals, preauthorizes the entire selection and then applies each through the existing revision/manual-override gate. Concurrently stale proposals are skipped and counted. It makes no provider requests and is not an all-or-nothing transaction across proposals.

## Storage and deployment

Schema 11 adds metadata ordering/FK indexes only: cached message date, deterministic decision/outbox ordering, collection owner/kind and rule/account lookups. It does not index message bodies, attachments or decrypted material. EXPLAIN QUERY PLAN on the synthetic upgraded database uses covering decision_owner_runs and mail_messages_time indexes for the existing owner/date and account/mailbox/date queries, without the previous temporary sorting B-tree. This is plan validation, not a production latency benchmark. Upgrade with the normal backup procedure; rollback to a binary supporting only schema 10 requires restoring the corresponding pre-upgrade database backup. Never edit schema_migrations to bypass compatibility refusal.

## Remaining scope

This does not implement a persistent unlocked worker, inline decryption/autopreview, signed-only mail or an AND/OR rules builder. Rule drafts from filters still require reviewing an individual sender/subject condition and explicit enable consent. No claim of 1.0 completion is made.
