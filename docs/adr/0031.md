# ADR-0031: Shared, bounded local filter expressions

Status: accepted. Extends ADR-0027 beyond header-only conditions; the original sender/domain/subject rules remain compatible.

Timeline search and local Space rules use the same deterministic parser/evaluator. No eval, regular expressions, SQL interpolation, plugins, model calls or external fetches. Plain unstructured searches retain metadata phrase matching. Structured predicates support from/to exact addresses, domain exact domain, subject/body substring and metadata substring, with uppercase AND/OR, implicit AND and parentheses. AND binds more tightly than OR. Quoted phrases and escaped quotes/backslashes are supported.

Limits: 2,048 UTF-8 bytes per expression, 64 tokens, 16 conditions and four parenthesized nesting levels. Body predicates scan at most the first 64 KiB of ordinary cached preview text; no body index is created. Search never matches body predicates on encrypted mail. Automatic rules still exclude own, encrypted and unsupported messages entirely, and reauthorize account/source/UIDVALIDITY and manual revisions before writing. Browser-decrypted content remains unavailable to this backend evaluator; this ADR grants no decrypted export permission.

Schema 12 adds a bounded expression column with an empty default. Existing basic rules use their unchanged semantics. Advanced rules store the reviewed user-authored query; compiled predicates are transient. Creating/editing a rule disables it, increments its revision and requires the existing preview/enable workflow. Existing capacities (32 rules, 50 new applications/pass, receipt/membership caps) remain. Processing and previews check cancellation between messages. Preview is not a full provider-archive search.

Create-rule drafts include the current search and optional person scope, preserving expression meaning through a parsed canonical representation. Selected Space is a destination; current date and label filters are explicitly not copied into the rule. No rule is silently created or enabled from search or manual assignment.

Take a database/keyring backup before migration. A downgrade to a pre-schema-12 binary requires the matching pre-upgrade database backup. Do not edit migration records to bypass compatibility checks. Rule query values and bodies are never added to logs or model traces.
