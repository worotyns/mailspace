# ADR 0008: Mail endpoints, TLS and encrypted provider credentials

Status: accepted · 2026-11-12.

## Decisions

Outbound mail connections default to denied. The operator approves exact normalized host:port pairs through MAILSPACE_MAIL_ENDPOINTS. A separate MAILSPACE_PRIVATE_MAIL_ENDPOINTS list explicitly permits LAN/loopback endpoints. No user-supplied URL scheme, path, arbitrary proxy or automatic provider discovery. Both protocols must authenticate over verified TLS before account creation/update commits.

Public endpoints validate every DNS result, reject private/special addresses, and dial the validated numeric IP without a second lookup. TLS ServerName remains the original approved hostname. Implicit TLS and mandatory STARTTLS are supported; no plaintext mode, no silent fallback, no skip-verification setting. Minimum TLS 1.2. An operator may add a trusted public CA PEM file through MAILSPACE_MAIL_CA_FILE; ordinary users cannot bypass validation.

IMAP: emersion/go-imap/v2 v2.0.0-beta.8 (MIT), pinned behind the internal connector boundary. It remains a prerelease dependency; upgrades require transport/interop regression tests. SMTP: emersion/go-smtp v0.25.1 (MIT), SASL through emersion/go-sasl. IMAP supports AUTH PLAIN or LOGIN after TLS; SMTP currently AUTH PLAIN. Provider OAuth is not implemented. Protocol debug writers are disabled. Remote authentication errors are replaced with fixed stage errors so a hostile server cannot reflect a password into UI/logs.

Connection checks have a ten-second budget per protocol, cancellation closes the socket, four concurrent checks globally, ten attempts/minute per authenticated user, bounded form bodies. Creating/updating an account is one SQL transaction after both probes succeed. Owner access is checked before probes and again by the transaction. Credentials are never returned by configuration views or generic serialization/formatting.

## Credential storage

Migration v2 adds mail_connections, separate from user password hashes. Both provider username and password are encrypted with standard Go AES-256-GCM using NewGCMWithRandomNonce. Associated data binds owner id, account id, protocol and envelope version. Account names, sender addresses and endpoint metadata remain metadata, not encrypted mail contents.

The random installation keys are outside SQLite in a 0700 directory, with 0600 key files and a durable active marker. Existing encrypted rows require the existing complete keyring; startup refuses to generate a replacement silently. Database-only disclosure does not expose provider passwords. Compromise of the running backend or the database AND key directory remains outside this at-rest protection.

Rotation persists/syncs a new key before activating it and re-encrypts rows in a SQL transaction. Old key files are retained. An interrupted transaction remains readable by key id; run rotation offline and retry after failure. Never delete old files automatically. Backup/restore includes the key directory. These are IMAP/SMTP login credentials only: OpenPGP private keys/passphrases and decrypted mail never enter this vault.

## Development fixture

make dev-mail is a loopback-only, non-relaying TLS IMAP/SMTP fixture. It generates a local CA/server key and random fixture password in ignored developer data. It seeds six real MIME conversations (sixteen messages); the UI-only encrypted placeholder is deliberately omitted. Restart changes UIDVALIDITY because in-memory contents reset. Production images do not run this server.
