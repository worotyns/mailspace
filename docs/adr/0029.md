# ADR-0029 — Spaces-only workflow, bounded dialogs and local archive

Status: Accepted. Migration 010. Extends ADR-0016/0019, preserves message-source authorization.

Threads open as a native modal right-side drawer over the unchanged timeline. Each open authorizes current sources; up to 100 cached messages are resolved, never fetched from IMAP by opening a thread. Replies still target one original message/account/References. Thread DOM/form IDs are distinct from the background; closed/swapped local attachment readers revoke object URLs and discard buffers. Native dialog Escape, close and focus behavior is retained; no custom focus trap or root scroll locking.

Spaces are the sole visible classification concept. All owned Space chips are immediately available per message (32 Space limit), without an expansion step. Labels are retired from routes/forms/navigation and cannot be assigned via the UI endpoint; existing stored definitions/memberships are preserved, not silently deleted or converted. Relevance never grants access. Recent stored Jev results show the overall decision confidence and proposed Space names, not an invented per-Space calibrated probability. Saved results can become stale; Apply retains all revision/consent/manual gates.

The People directory aggregates only owned cached sources, renders 50 entries/page, supports explicit server-side search, and keeps only six sidebar shortcuts. Tests exercise 20,000 unique cached correspondents; this is not a provider address-book import. Decision history remains the latest 50 runs with a 5,000/user receipt cap. Cmd/Ctrl K opens a native command dialog. Explicit Jev recheck previews at most three eligible unassigned cached ordinary messages under existing saved provider/payload consent, reusing matching stored attempts. Preview never applies proposals. A separate explicit saved-mode action honors Manual (preview), Review (proposal) or Auto (apply ≥80% confidence). Neither action enables a provider, bypasses gates, includes archived/encrypted/own mail or creates an unlimited scan. Existing six attempts/minute limit applies.

Archive is local, owner/account-generation/message-scoped metadata. It hides messages from active/Unsorted/Space views, leaves All activity and Archived accessible, and preserves sources/assignments. Restore reverses the archive flag. Both changed actions advance manual revision, rejecting late classification/rule application; restoring does not erase manual authority. No IMAP move/delete/flags, remote Spam training or shared access is introduced.

Migration 010 adds nullable palette_color with a 16-value allowlist alongside the original checked six-color column, avoiding a destructive parent-table rebuild and preserving old colors. New values use a legacy fallback only in the old column. It also adds reference-only message_archives with account cascade. Rollback requires pre-upgrade database/keyring plus matching image restored into a fresh volume; do not open schema 10 with an old binary.

Attachments are discovered on explicit click using the existing owner-scoped bounded raw MIME endpoint, then decoded/downloaded locally. Ordinary MIME metadata includes attachment names/types; encrypted previews expose none. Text/JSON previews use textContent with a 256 KiB UTF-8/NUL bound. PNG previews require byte signature and dimension/size bounds (4 MiB, 4096 per axis and 16 MP); other files download without execution. HTML/SVG/PDF are not rendered as attachment documents. Parent reader/timeline CSP permits only blob: images; remote image/script/frame/navigation resources remain denied, and sanitized mail HTML retains its separate opaque sandbox with img-src none. No new backend attachment body/index, private key path or decrypted export is added. Buttons disable after serialization and during work, preserving explicit submitter consent and preventing duplicate actions.
