# ADR-0027 — Reviewed local header rules

Status: Accepted. Migration 009.

Local rules assign individual ordinary incoming cached messages to owned Spaces using an exact sender, exact ASCII/punycode domain (no implicit subdomains), or case-insensitive subject phrase. They do not inspect bodies, decrypted content or attachments, call models, send mail, mutate provider flags, or grant access. Multiple rules may assign one message to multiple Spaces.

Saving or editing leaves a rule disabled. Preview is read-only. Explicit authenticated, owner-scoped, Origin/CSRF-protected enable consent covers eligible cached and future messages. Manual membership revisions veto subsequent automation, including manual removal. Rule/source/account revisions and ownership are rechecked transactionally. Metadata-only receipts prevent repeated application. Removing or disabling a rule preserves existing assignments.

The existing successful mailbox sync invokes bounded local processing; there is no separate scheduler. With no enabled rules no source listing is performed. Limits: 32 rules/user, 50 new decisions/pass, 5,000 receipts/user and 50,000 memberships/user. A preview lists at most 50 eligible matches. Capacity failures stop work; they do not delete prior assignments. No archived-spec replay contract is promised by this slice.

Migration 009 adds rules and reference-only receipts. Rollback requires restoring a pre-upgrade database, credential keys and matching image into a fresh volume. Tests cover disabled state, idempotency, manual veto, stale revision, multiple Spaces, body exclusion, encrypted/own-message exclusion, two-user isolation and HTTP consent/CSRF. No provider-side spam action is implied by a Space named Spam.
