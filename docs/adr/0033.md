# ADR-0033: Sidebar label filters and inline message statuses

Status: accepted. Supersedes only the no-sidebar label decision and footer label placement in ADR-0030, following use of the product.

Labels are optional private status metadata, distinct from message-level many-to-many Spaces. Show them as quick filters below Spaces in the sidebar, with the same account-scoped active cached-message counts used by the timeline. Names and colors remain editable in Settings. This restores fast access to workflows such as Todo and Done without adding provider folders or another timeline.

Each individual message, including a grouped continuation, shows its assigned label badges alongside sender/account metadata. A native auto popover opens a compact badge chooser without expanding the message row. It uses one native popovertarget invoker (no double-toggle command), light-dismiss/Escape and scoped focus restoration. A working details/form disclosure remains the progressive fallback without JavaScript or Popover support. Each label is an independent toggle; names such as Todo and Done do not imply mutually exclusive groups. After each successful metadata-only change the chooser reopens with focus on the changed badge, so users can remove Todo and add Done without reopening it. Original-thread and person bulk label tools remain available.

The existing owner-scoped, CSRF-protected collection membership POST remains the mutation contract. Its label-targeted response replaces only that message's label control and updates sidebar counts out of band. It never replaces the message body or composer, so browser-only decrypted content and drafts survive. Native form navigation remains the no-JavaScript fallback. The current row may remain visible after removal of the active label until refresh/navigation; preserving an unsent draft takes priority over silently rebuilding the timeline.

No schema, crypto/export boundary, automatic rule, Space membership or manual Space-override behavior changes. There is no new dependency, model call, mail-server mutation or label exclusivity. Rollback restores the prior presentation and retains all memberships unchanged. Regression tests cover scoped feed/drawer IDs, grouped message controls, safe escaping, header placement and metadata-only responses.


MS-022 polish: label choices use the owner's colors as small pill badges with explicit +/check and aria-pressed state; touch targets remain separate from the compact visual outline. The local enhancement moves only trusted metadata controls into the native top layer, clamps position to the viewport and flips above a low trigger. User scrolling outside dismisses it; programmatic scroll from native focus must not immediately close a newly opened popover. No label/body text enters a new request or HTML sink. Sender/People names now show the plain email address as secondary escaped text so identical names remain distinguishable.


MS-022 header identity polish: each started run shows one identity pair as two lines instead of repeating a display name. Received mail shows `sender name → account name` on the first line and `sender address  account address` on the muted second line. Mail this user sent shows `You → recipient summary` (the first non-account `To` address plus a count when more were addressed) and `account address  first recipient address` beneath it, because cache previews keep addresses, not recipient display names; inventing a contact name would be dishonest. A Unicode arrow marks the direction and the meta row stays vertically centred. This applies to the timeline, Spaces, label/person/query filters and the original-thread drawer because they share one message template. If an account is named after the same person, that name appears on both sides of the arrow; rename the account to a mailbox label. It changes presentation only: no new lookup, request, model call, storage or export, and Bcc recipients stay absent from the visible summary.
