# ADR-0033: Sidebar label filters and inline message statuses

Status: accepted. Supersedes only the no-sidebar label decision and footer label placement in ADR-0030, following use of the product.

Labels are optional private status metadata, distinct from message-level many-to-many Spaces. Show them as quick filters below Spaces in the sidebar, with the same account-scoped active cached-message counts used by the timeline. Names and colors remain editable in Settings. This restores fast access to workflows such as Todo and Done without adding provider folders or another timeline.

Each individual message, including a grouped continuation, shows its assigned label badges alongside sender/account metadata. A native details disclosure opens an in-flow, keyboard-accessible chooser. Each label is an independent toggle; names such as Todo and Done do not imply mutually exclusive groups. After each successful change the chooser remains open, so users can remove Todo and add Done without reopening it. Original-thread and person bulk label tools remain available.

The existing owner-scoped, CSRF-protected collection membership POST remains the mutation contract. Its label-targeted response replaces only that message's label control and updates sidebar counts out of band. It never replaces the message body or composer, so browser-only decrypted content and drafts survive. Native form navigation remains the no-JavaScript fallback. The current row may remain visible after removal of the active label until refresh/navigation; preserving an unsent draft takes priority over silently rebuilding the timeline.

No schema, crypto/export boundary, automatic rule, Space membership or manual Space-override behavior changes. There is no new dependency, model call, mail-server mutation or label exclusivity. Rollback restores the prior presentation and retains all memberships unchanged. Regression tests cover scoped feed/drawer IDs, grouped message controls, safe escaping, header placement and metadata-only responses.
