# ADR-0026 — Fresh mailbox connections and explicit recent-history import

Status: Accepted. Migration 008; preserves legacy account behavior.

New account setup defaults to fresh mode. At the first successful snapshot of each folder/account generation/UIDVALIDITY, record the highest existing UID, and skip downloading existing bodies. Subsequent new UIDs sync under normal read-only limits. Snapshot metadata still reaches the backend to establish this boundary; fresh does not mean a metadata-blind connection. The cutover is first successful observation, not wall-clock account creation.

An explicit account-settings action, without re-entering provider credentials, may enable recent import (latest 500 per folder, existing byte/call/storage bounds). It requires authentication, source ownership, Origin/CSRF and separate approval. Changing mode does not enable a model or remote mail mutations. Already cached mail remains within the existing bounded cache behavior. Existing installations/programmatic fixture accounts retain recent behavior until changed; no silent deletion/migration of private mail. Full archive pagination remains MS-018, not an implied capability of this recent import button.

Settings revisions invalidate in-flight commits after policy changes. Baselines survive process restart and are replaced on account-generation or UIDVALIDITY changes, with stale folder bookkeeping pruned. Cached originals/collection references retain their existing current-source checks. No private key or decrypted-content path is added.

Tests cover no initial historical body downloads, later incoming mail, restart, explicit import, preservation of cached originals, UIDVALIDITY reset, stale policy commit rejection and two-user/CSRF/approval boundaries. Rollback requires a pre-migration database/keyring/image restored into a fresh volume; no destructive down-migration.
