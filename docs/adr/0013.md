# ADR 0013: Browser-owned signed encryption and opaque MIME submission

Status: accepted · 2026-11-13. MS-006 is in progress, with explicit interoperability gates still open.

## Sending boundary

A dedicated native secure composer owns its unnamed controls in an hx-disable region. It has no HTML form; CSP form-action none prevents accidental serialization. It reads passphrases only to unlock a protected local key, clears the field, and signs/encrypts the canonical MIME entity with OpenPGP.js in memory. Every To/Cc/Bcc address plus the owner's From address must have an explicit current fingerprint binding. The unlocked signing key must match From. Expiry/revocation/identity are revalidated on every send. A changed or missing recipient blocks output. Bcc recipient key IDs are hidden using wildcard PKESK; envelope recipients and message size remain visible to the server.

The only submission payload is an allowlist of visible routing metadata, request nonce, optional authorized parent locator and encryptedMime. There is no generic body, key, passphrase or decrypted-content field. Unknown JSON fields are rejected. The route requires session, exact Origin, CSRF and the existing connection budget. The server validates a bounded two-part multipart/encrypted entity and armored PGP MESSAGE structure. It reconstructs the outer MIME to strip arbitrary preamble/epilogue/part headers and generates authoritative From/Date/Message-ID/References. It does not decrypt, verify an inner signature, or claim that structural armor validation proves recipient trust/decryptability. A malicious client can always submit garbage; it cannot ask the backend to handle its private keys or plaintext through this contract.

The existing durable outbox retains its owner, revision, nonce/digest, capacity, pending→sending claim, SMTP unknown-result and independent Sent-copy semantics. Once submission starts, the browser does not re-encrypt/retry automatically. After interruption the user checks Outbox/provider before making another send. Replies authorize the original account/folder/UIDVALIDITY/UID and derive references from original MIME. No decrypted quote is requested by or sent to Go. Ordinary plaintext compose retains per-message consent and refuses encrypted-parent downgrade. Primary mailbox composition uses the secure path; the ordinary composer is an explicit fallback.

## Reading boundary

The owner-scoped /api/mail/raw endpoint checks account generation and UIDVALIDITY/UID through the same original-MIME service. It returns an attachment/octet-stream with no-store and nosniff, never rendered mail HTML. A native client reader fetches only this ciphertext, validates the bounded OpenPGP/MIME envelope and decrypts in local private memory. Decrypted bytes are tagged client-decrypted and parsed with postal-mime 4.2.1 (MIT-0, zero runtime dependencies), locally bundled. Bounds: 4 MiB input/decompressed content, 12 MIME nesting levels, 100 parts, 64 KiB aggregate headers, no inline nested message expansion. The outgoing text body is bounded to 256 KiB.

Only textContent renders the resulting plain text; no mail HTML, remote image or decrypted markup is inserted. Attachments download explicitly via transient browser Blob URLs with octet-stream type and safe filenames. Lock removes displayed text/attachments, revokes URLs, clears draft/passphrase controls and invalidates pending operations. Five-minute inactivity, hidden tab, departure, expiry and cross-tab session signals lock. No backend draft/autosave, AI, rule action, index, telemetry or webhook receives decrypted output. JavaScript RAM/host/operator limitations from ADR-0012 still apply. Subject and routing metadata are not protected headers.

Signature validity and sender identity are separate: unsigned, unknown key, invalid signature, valid but untrusted key, and valid signature matching an explicitly bound sender are distinct labels. Imported public keys can establish mathematical validity without establishing identity. Outer From is an untrusted claim, checked against the explicit local binding; it is not itself authenticated by the parser.

## Compatibility and remaining gates

This first integrated path supports ASCII-armored multipart/encrypted with an embedded OpenPGP signature. New messages use CRLF MIME and an interoperable base64 UTF-8 text part. GnuPG round-trips exercise the application vault/MIME path. Detached multipart/signed read/send, binary encrypted parts, imported legacy layout variants, encrypted drafts/attachments in composer, secure quote UX and Thunderbird round-trips remain open MS-006 work. The global openpgp capability stays false until that acceptance matrix is completed; encryptedMimeAlpha separately describes the available path. Unsupported forms fail visibly without plaintext fallback. There is no claim of production-ready 1.0 crypto yet.

## Recovery

No backend schema migration. The outbox stores original ciphertext in its existing bounded raw column. Never resend unknown entries when downgrading a binary; export key backups independently of server backups. Original encrypted mail can be downloaded for another compatible client. No public plugin contract is opened.

ADR-0014 subsequently implements the encrypted local draft and small attachment composer portions of the remaining gates above. Other compatibility gates remain open.
