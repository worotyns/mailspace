# ADR-0044: Cached recipient display names and honest To/Cc

Status: accepted for MS-022 implementation.

Cache previews stored only recipient addresses, so sent mail could show a recipient address but never a name and received mail never showed Cc. This adds recipient display names and Cc metadata to the existing bounded preview, plus a header-only repair for already cached rows. It changes cached metadata, not the storage engine, authorization model or any export boundary.

## Cached metadata

`mailsync.Preview` gains `RecipientsVersion`, `ToRecipients` and `CcRecipients` (each a display name plus address, at most 100 entries, name 200 and address 254 bytes). The existing `To []string` address list stays authoritative for filtering, rules, decision input and reply prefill, so no consumer changes behavior. New messages fill both in `Parse`. `RecipientsVersion` makes the shape explicit and lets older rows be upgraded.

Existing cached rows are upgraded lazily by the same bounded, header-only repair already used for threading: at most 500 rows per folder read, at most the first 64 KiB of the original message, a complete header terminator required, and one conditional `UPDATE` per row that fails closed on a changed owner, account revision, UIDVALIDITY, prefix or preview. No body is decoded, no MIME is rendered, no remote request or redownload happens, and no decrypted material is read or written.

## Display and privacy

The sent identity line shows a cached recipient display name when present and the address beneath it; the received line appends `cc: …` when cached Cc recipients exist. The full reader shows a `To`/`Cc` metadata block from the cached headers, with a short note that recipients come from cached headers and are bounded to four plus a count. Received mail has no Bcc header to show and none is invented; an outgoing Bcc stays envelope-only, owner-scoped outbox metadata and is not parsed back from the sent MIME or displayed by this slice.

The People directory and recipient suggestions now cover both directions: cached senders plus the cached To/Cc recipients, deduplicated by address, excluding the account's own address and the sender. Suggestions therefore include people this user has written to, not only people who wrote to them. The client datalist still sends only the typed recipient fragment, keeps the earlier recipients intact, discards stale/aborted responses, and leaves free-form entry available when suggestions fail.

No model, provider, index, schema column or new dependency is introduced; the preview JSON is additive and old readers ignore the new fields. Rollback stops repairing and ignores the new fields; existing addresses and `To []string` remain valid. Tests cover name/Cc parsing, bounded header repair with no body leak and idempotence, the two-line identity rendering, the reader block never showing Bcc, two-way People aggregation and the client stale-response/prefix behavior.
