# ADR-0041: Bounded timeline pages and upward cached-history loading

Status: accepted for MS-022 implementation.

Root timeline views initially render the latest 20 authorized matching cached messages in chronological order, with the newest at the bottom. Older pages contain at most 20 more messages. The original thread drawer keeps its existing separately documented 100-message limit. Shared source/rule/bulk/People scopes and sidebar counters remain based on the full bounded cached view; UI pagination must not silently narrow them.

## Cursor and authorization

A versioned bounded base64url JSON cursor contains only an opaque logical message key and SHA-256 of the canonical owner/timezone/account/filter view. It is a locator, never an authorization capability or a secret: every request repeats current owner/account/revision/UIDVALIDITY/source and filter checks, and the anchor must still exist in the authorized matching list. Invalid/unknown-version/foreign-scope/stale cursors fail closed; they never fall back to dumping another view. Ordering reuses the source's timestamp and deterministic identity tie-break. Newer arrivals do not shift the anchor boundary. No body, mail headers, ciphertext, keys, consent or decrypted material enter the cursor. No schema or storage change is needed; rollback removes the additive UI/query contract.

Native older links navigate to a complete bounded page, with a Latest link to restart. Enhanced links request a dedicated same-origin protected HTML fragment containing only older-message rows and the next history control. HTMX uses explicit target/outerHTML and no form parameters, no push/history snapshots, allowEval/allowScriptTags=false and existing no-store/CSP boundaries. The initial reply selection remains visible even when its cached source is older than the default latest window.

## Mounted content and scroll

Upward scrolling requests one page at a time near the top. A native older link remains available to keyboard/no-JS users. Loading, retry, stale-source and end-of-current-cache states stay visible. There is no automatic retry loop on a failed request. The client preserves a retained row's viewport position after prepending and synchronous inert text enhancement. Existing message nodes, local decrypted content, readers and authored composer controls remain mounted. Newly loaded encrypted rows join the existing local reader without clearing older previews. Requests are aborted/ignored on root replacement or pagehide. No decrypted DOM, textarea, passphrase or key is read or serialized for paging.

This paginates the existing bounded cache (up to 1,000 consolidated entries and current per-folder/outbox limits), not arbitrary provider history, retention or native IMAP IDLE. No provider/model request, new dependency, mail flag mutation or send occurs. Security tests cover owner/filter/timezone/anchor scope, unknown/expired source, no snapshot/egress, stable ordering, 20-row bounds, native fallback and retained DOM/scroll/composer behavior.
