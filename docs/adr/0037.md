# ADR-0037: Explicit authored signed-only transport

Status: accepted for the bounded signed-only transport slice. Extends ADR-0028; no generic decrypted export permission.

`POST /api/outbox/signed` accepts only a bounded, canonical seven-bit multipart/signed MIME entity produced from authored text and up to ten binary attachments (1 MiB total), separately supplied envelope metadata, `provenance: authored` and explicit `allowPlaintext: true`. The user-facing action must say that the message and attachments are unencrypted and will be stored and sent as readable mail. A signature provides integrity/authenticity, never confidentiality. The provenance assertion is a client contract, not proof against a malicious same-origin client; the same trusted application must never source this action from decrypted content or silently quote it.

The allowlisted JSON decoder rejects unknown fields, keys, passphrases, generic body/ciphertext alternatives and non-authored provenance. The structural MIME validator requires exactly two parts, fixed PGP signature protocol/SHA-512 micalg, no unsigned client envelope headers or decorations, and a first part limited to UTF-8 base64 text/plain or one multipart/mixed of that text and base64 binary attachments. No HTML, nested message, encrypted entity or recursive multipart is admitted. Headers, part count, size, names and line endings are bounded. The server does not claim to verify cryptographic validity or sender trust; those remain client responsibilities.

The server supplies authoritative From, To/Cc, Date, Message-ID, Subject and original References/In-Reply-To. Bcc exists only in the SMTP envelope and private owner metadata. Exact inner and signature bytes are retained through durable outbox, SMTP and Sent APPEND. An encrypted original is always refused for signed-only replies, including typed outbox/IMAP references. Existing ownership, CSRF, account/source revision, transactional UIDVALIDITY freshness, durable nonce and single-attempt dispatch guards apply unchanged. Unknown SMTP results are never retried automatically.

Signed mail is intentionally ordinary readable mail in backend storage/cache and can follow existing ordinary-mail rules; it is not client-decrypted provenance. This endpoint cannot authorize exporting decrypted material. Existing encrypted-send payloads and generic export denial remain unchanged. No schema migration, dependency or provider is added. New optional draft fields are omitted from old JSON hashes, preserving existing nonce input hashes across upgrades. Rollback restores the prior binary; already stored signed MIME remains ordinary readable mail.

The transport slice must pass format/boundary, exact-octet, owner/CSRF, encrypted-parent, stale-source and no-resend regressions before commit. A visible client action, app → HTTP → SMTP/Sent → GnuPG interoperability and real Thunderbird acceptance are separate required checks before claiming complete signed-only sending or MS-006/1.0 completion.
