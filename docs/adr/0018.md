# ADR 0018: Unified message timeline and optional inline encryption

Status: accepted · 2026-11-13. Implements the next UI slice of ADR-0016/0017.

Spaces/People/labels/date are views of the same chronological source feed. All activity and Unsorted are useful without any classifier. Source account/configuration/UID generation authorization is repeated for reads, assignments and replies. Native forms and URLs remain available for ordinary operations. Private collections are not team sharing; organization membership grants no source access.

The inline composer targets one typed IMAP or Outbox source. Original References/In-Reply-To and From derive from that authorized source on the server. Explicitly sending from a Space assigns the outgoing source only to that Space. IMAP folders and full reader/composer remain an advanced fallback. This slice has metadata search and a bounded recent cache, not full history or a content index.

Ordinary user-authored text uses an explicit Send unencrypted action. Selecting Encrypt immediately removes its body field name, disables HTMX on that form and intercepts submit before HTMX. The small key-unlock dialog has no named or form-owned private controls. An allowlisted JSON request contains only visible addressing/topic metadata, nonce, typed source, optional private Space and locally signed/encrypted MIME. The backend refuses unknown JSON fields and mixed old/new parent locators. Local keys/passphrases/plaintext never enter the payload. An encrypted original mandates encryption and its server-side downgrade guard remains authoritative.

The browser loads the crypto controller only on use. It verifies all recipient/sender bindings through the existing LocalVault, locks on inactivity/hidden page/session broadcast/expiry/navigation and disposes on HTMX replacement. Unlock and send are distinct actions. Missing keys block sending and lead to the advanced Local keys screen; no silent discovery/trust/downgrade. Once a ciphertext POST begins, the composer will not submit again even after a transport error. Outbox exposes the definitive accepted/rejected/unknown state; server acceptance is not delivery. Attachment/local draft controls remain in the advanced composer pending a later UX slice.

No new storage migration, provider client, model, index, webhook or third-party request is introduced here. Existing migration v6 and backup/downgrade rules apply. The approved isolated HTML renderer is unchanged.

Validation: Go rendering/escaping/unnamed encrypted-parent fields, typed outgoing original references, owner/revision denials, HTTP timeline and expired-session behavior, strict encrypted JSON/typed-source rejection, plus an actual inline-controller test decrypting the captured ciphertext and checking private canaries never enter the request. Full make check includes race tests, vet, client tests and actionlint. Native browser checks cover ordinary send and keyless modal, desktop/mobile scrolling and Escape.
