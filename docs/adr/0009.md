# ADR 0009: Bounded read-only mail cache and conversation identity

Status: accepted · 2026-11-12.

## Decisions

Personal mode reads real mail; demo fixtures never populate a personal mailbox. Migration v3 adds mailboxes and mail_messages plus a connection revision. IMAP identity is account + exact mailbox name + UIDVALIDITY + UID, never sequence number or Message-ID. Configuration updates increment the revision and discard the old cache in the same transaction. Every snapshot commit verifies owner and revision, so an old connection cannot write into a changed account.

The initial alpha retains the latest 500 message locators per selectable folder, at most 32 folders. Metadata is fetched in pages of 50 under EXAMINE, bodies through UID BODY.PEEK. A changed message count/UIDVALIDITY during pagination fails the snapshot rather than treating a partial response as deletions. Reconciliation changes only local cache rows. Flags and expunges are refreshed on subsequent sync; the app does not mark messages Seen or delete mail remotely.

One cycle downloads at most 20 new bodies / 16 MiB, each at most 4 MiB. Original MIME occupies at most 64 MiB per account. Pending rows are durable download checkpoints; subsequent cycles resume them. Oversized messages retain a visible placeholder and stay on the server. This is a bounded recent-mail window, not full-history synchronization. A complete mailbox snapshot is atomic; successful folders may commit before a later folder fails. Missing folders are pruned only after the entire pass succeeds. No backend full-text index is created.

The transport closes on cancellation and has a 25-second cycle budget. A single in-process sync gate avoids overlapping snapshots. The bounded, nonblocking onboarding queue schedules newly connected accounts. A polling worker scans eight accounts per minute with a round-robin cursor; no account list is held open during network work. Manual refresh is also available. Native IDLE/full-history optimization is deferred to MS-018; polling is the current portable fallback. Shutdown cancels the worker before closing SQLite.

## MIME and privacy

Original provider MIME is cached unchanged, including ciphertext. Ordinary unencrypted messages may have a cached text/plain preview; the database is sensitive mail storage, not encrypted at rest by this feature. Protect the full data directory and backups. Credential encryption does not encrypt the mail cache.

MIME is parsed with emersion/go-message v0.18.2 (already pinned, MIT). A 64 KiB top-header limit, 12 nesting levels, 100 parts and 64 KiB decoded text limit bound preview work. HTML, remote resources and attachments are not rendered or fetched. Unsupported MIME becomes a visible no-preview state. Any encrypted MIME part or inline PGP armor makes the whole preview opaque, discarding plaintext siblings. No GPG private key, decryption, AI, webhook or content index is involved. Signature verification is not implied by displaying a signed message's plaintext.

Threading uses unambiguous Message-ID references within one account and folder. Duplicate ids remain separate; missing parents fall back to separate conversations. Subjects alone never join messages. Reference cycles are bounded by a disjoint-set grouping operation. Thread grouping is a presentation heuristic, not authentication or a future sharing ACL boundary. Cross-folder conversation unification and full standards/provider interop remain later work. Classical view is available, with the same account authorization.

## Rollback

Forward-only schema v3. Older binaries refuse newer versions. Restore the complete offline pre-migration data/keyring backup to roll back; do not drop cache/schema tables manually on a live installation.
