# ADR-0046: Local full-text index over cached ordinary text

Status: accepted for MS-012/MS-014. Supersedes only the "no new body index" constraint of ADR-0031; the rule/automatic-matching behavior stays unchanged.

Plain word search previously matched sender, recipients and subject only. The `body:` predicate matched cached preview text in memory. This ADR adds a local SQLite FTS5 index over ordinary cached preview text so plain words also find message text, without a model, embedding, remote service, or any new provider request.

## Scope and data

Migration 015 creates `message_search` (FTS5, `unicode61 remove_diacritics 2`) and triggers that mirror `mail_messages` inserts, preview-text updates and deletes by rowid, then backfills existing rows from `json_extract(preview, '$.Text')`. Only cached ordinary preview text is indexed. Encrypted previews carry no text, so ciphertext never enters the index; keys, passphrases, client-decrypted material, provider credentials and outbox envelopes are never indexed. The index duplicates the already-cached preview text (bounded by the existing 64 KiB preview cap) and lives in the same SQLite file with the same sensitivity.

## Query semantics

Plain word queries (no field prefix, `AND`/`OR` or parentheses) union the legacy metadata substring match with the index: a record matches when every typed term is found in sender/recipients/subject or the indexed body. Structured queries such as `from:`, `to:`, `domain:`, `subject:`, `body:` and `AND`/`OR` keep their exact legacy in-memory evaluation, so their semantics do not change and `body:` still works without the index.

User words become an FTS5 expression of quoted phrases joined by implicit AND. Quoting and doubling embedded quotes make operators and punctuation (`"`, `*`, `NEAR(`, `OR`) literal. Terms are capped at 16, each term at 64 runes, accounts at 64 and results at 2000. `SearchText` never authorizes anything: it queries only the account ids the caller already resolved as readable, so owned plus currently granted accounts keep their existing scope, and a foreign account id can never return rows.

## User experience

The search field now states that plain words also search ordinary cached message text, the feed shows a matching-count status line, and an empty search shows a dedicated "No matches in cached mail" state that explains text search covers ordinary cached mail and not encrypted or uncached provider history. Results keep the chronological timeline order; this slice does not add relevance ordering or snippets.

## Rollback

Migration 015 is forward-only; restore the pre-upgrade database backup to roll back. Dropping `message_search` and its triggers removes the index; plain search then falls back to metadata substring matching, and structured queries are unaffected. No cached message, credential, collection or grant row changes meaning.
