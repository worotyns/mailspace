# ADR-0036: Safari worker module CSP compatibility

Status: accepted. Extends ADR-0032; no storage migration.

## Evidence and correction

Native Safari rejected static imports of vault.mjs, store.mjs and session-core.mjs with “does not appear in the worker-src directive”, although the worker entry returned HTTP 200 and script-src permitted self. The shared and dedicated entrypoints therefore failed before session authentication; the unlock dialog could not list keys.

The worker response now permits exactly the six local dependency URLs in worker-src: vault, store, errors, session-core, vendored OpenPGP and idb. The worker entrypoint, unrelated application scripts, blob and external sources are not admitted. script-src remains self. This is a compatibility concession: these trusted dependency files could themselves be used as child-worker entrypoints, but no arbitrary same-origin path is permitted for hostname origins or 127.0.0.1. Those modules implement no child-worker creation.

For literal IP origins other than 127.0.0.1, CSP host-source matching cannot express these URLs reliably. worker-src uses self, as connect-src already does for such origins; external origins and blob stay denied. Production HTTPS hostname deployments use the exact URL list. The worker is trusted same-origin application code, not an XSS boundary.

connect-src still permits only the fixed session metadata endpoint on hostname origins/127.0.0.1. RPC arguments, private keys, passphrases and decrypted content never enter fetch. There is no unsafe-eval, remote dependency, new provider, persistent unlock, or automatic operation replay change. Keys-page connect-src remains none.

## Validation and rollback

Regression checks cover the fixed allowed module URLs and reject broad worker-src self, unrelated scripts and the worker entrypoint for hostname deployments. Native Safari now lists the local vault and imports a protected synthetic key; the full browser acceptance result is recorded separately. Rollback restores the earlier worker-src none policy and its Safari failure; no database or vault changes are needed.

Native Safari acceptance (2026-11-15): isolated IPv6 loopback devsandbox; protected synthetic .test key imported, identity fingerprint verified, composer unlock succeeded, signed/encrypted message accepted by synthetic SMTP, inline local preview recovered the exact test text and reported a valid signature with verified sender fingerprint. No real mailbox or key was used. The owned local server was stopped afterward. Hostname-source policy is covered by HTTP regression checks; this local run does not replace broader production/browser compatibility acceptance.

Release checks: `make GOTOOLCHAIN=go1.27.4 check` passed (78 client tests, formatting/build/license notices, go vet and race tests); gofmt and diff checks passed. Docker CLI was unavailable; `MAILSPACE_ORIGIN=https://mail.example.test podman compose config --quiet` passed, and `MAILSPACE_CONTAINER_CLI=podman scripts/check-runtime.sh` passed build, non-root/read-only runtime, health, local assets, anonymous API denial and persistence after restart. An earlier check collided with another dependency install; a clean repeat passed. No release tag was created.
