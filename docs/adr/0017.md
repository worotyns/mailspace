# ADR 0017: Typed source identities and private message-level collections

Status: accepted · 2026-11-13. Implements the storage/source foundation of ADR-0016; the new main UI is the next slice.

## Source identity

A typed source reference is either IMAP (account, connection revision, exact folder, UIDVALIDITY, UID) or Outbox (account, connection revision, outgoing id). Unknown/ambiguous kinds and stale generations fail closed. Source resolution rechecks owner/configuration and reads original MIME only; no network/provider/model operation is part of timeline listing or classification assignment.

Logical identity hashes account id, connection revision, Message-ID and the SHA-256 of original MIME. Exact same-id/same-byte copies across folders or Outbox/Sent collapse only within that namespace; conflicting IDs remain separate. Missing Message-ID uses a physical-reference fallback, so identical unidentified messages are not silently merged. This is intentionally conservative: copies changed by transit headers and cross-account copies are not guessed equivalent. Original References remain available, but a shared original email thread never merges timeline entries or Space memberships.

The ordinary preview stores a content hash as source metadata, not a content/semantic index. Older cached previews lacking it are lazily reparsed from already cached original MIME during a read, without a remote redownload or decryption. IMAP sources carry received timestamps/flags and exact revision checks. Outbox sources expose pending/accepted/rejected/unknown and independent Sent-copy state honestly, so an outgoing attempt can appear before mailbox synchronization. Its exact Sent copy later collapses without losing the certainty state.

## Spaces and labels

Migration v6 adds message_collections (private owner, kind space/label, name, description, palette color, revision), many-to-many reference memberships, and per-source manual revisions. It stores no copied mail body, private key or decrypted content. Spaces have editable relevance briefs; labels have no classification brief. Initial limits: 32 Spaces / 64 labels per owner, names 80 codepoints/200 bytes, Space descriptions 8 KiB, 50,000 memberships per owner. This slice has no workspace/shared scope; organization membership does not grant private collections or sources.

Every assignment authorizes the collection first, resolves a current typed original source, then atomically rechecks both owners and the connection revision before changing membership. Repeated identical selection is idempotent. Real manual changes increment a source revision in the same transaction; a failure rolls back both. Description edits use optimistic revisions. These epochs support a future model decision gate without allowing a late model to undo a human correction. Membership results are intersected with the live authorized source feed: deleted/vanished/reconfigured sources cannot become visible from a retained reference. Deleting a Space removes only its memberships, never original mail.

Classification sources have a bounded schema, but only manual writes are exposed in this implementation. No provider client, background model, classifier, index or public plugin API is activated by adding these tables. JEV dry-run/trace/replay and the optional provider adapter require their own implementing slice.

## Migration and recovery

Forward-only v6, added transactionally. v5 and older binaries refuse a v6 database; restore the complete matching offline DB/keyring backup for downgrade. Private browser vaults/drafts remain outside server backups. Connection revision changes deliberately isolate old source assignments; old references do not transfer to another configured mailbox. A future explicit same-source migration needs review rather than assuming a username/password update preserves source identity.

## Validation

Tests cover two distinct messages from one email thread assigned to different Spaces, one message in multiple Spaces, independent labels, repeated selection/manual epochs, removal without source deletion, owner/organization isolation, stale UIDVALIDITY/config rejection, atomic rollback on revision-write failure and optimistic brief updates. Timeline tests cover conservative duplicate handling, missing/conflicting ids, cross-account/config identity separation, old-preview hash recovery and Outbox→Sent deduplication with certainty state. Identity upgrade/newer-schema tests include v6. The account save result now returns its actual committed revision via SQLite RETURNING, with a regression check; callers no longer receive a misleading zero revision.
