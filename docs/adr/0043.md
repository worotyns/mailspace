# ADR-0043: Provider-synchronized read state

Status: accepted for MS-022 implementation.

Incoming synchronization stays read-only: it uses EXAMINE/BODY.PEEK and never sets Seen. This ADR adds a separate, bounded provider flag capability for read state only, plus automatic-after-open and a manual toggle in the message row. No move, delete, expunge, archive, keyword or folder change is introduced, and no cached body, preview, header or decrypted material is sent or logged.

## Capability and boundary

`mailnet.FlagWriter` is a distinct transport interface next to `Reader` and `Sender`. Its only method sets the `\Seen` flag of one UID on a fresh short-lived connection that selects the mailbox read-write, requires the caller's exact `UIDVALIDITY`, and confirms the server's returned flags before reporting success. Any other outcome is a normalized error, so the caller must keep local state unchanged.

The capability is on by default for personal mode and explicitly disableable with `MAILSPACE_IMAP_FLAG_WRITES=0` (also `false`, `off`, `no`). A disabled capability makes no remote call and the UI shows no toggle. The synthetic sandbox enables it against the local fixture. No new dependency, schema column or storage format is required; `flags` already exists per cached message.

## Authorization and confirmation

`mailsync.Service.SetSeen` authorizes the owner/account, requires the exact cached `account + mailbox + UIDVALIDITY + UID + connection revision` and a downloaded body, then contacts the provider through `WithIMAP` with a revision recheck. Only after the provider confirms does it update that one message's `flags` inside a transaction that rechecks the revision. A changed revision, foreign owner, unknown UID, stale `UIDVALIDITY`, non-selectable mailbox or unconfirmed response fails closed: the visible state does not flip, and the client must reload before assuming anything.

The HTTP contract is `POST /messages/seen` with CSRF/Origin validation, an explicit `seen=0|1`, a scoped encoded source reference and a `return_to`. It accepts only IMAP references; outbox rows have no provider flag. Read-state writes use their own per-user rate window and a two-slot concurrency bound, separate from the mail-send/connection budget, so ordinary reading can never block sending. The HTMX response is only the message's `seen-*` fragment; the rest of the row, its decrypted DOM and any composer draft stay mounted. Native form POST and redirect remain the fallback.

## Automatic and manual behavior

Opening a message's content is an explicit user action, never a timeline render. Automatic marking therefore happens when the user opens the full message reader or successfully decrypts an inline preview, and it sends the same bounded POST. Merely fetching, paging or refreshing a timeline never writes any flag and never marks cached mail read. The manual toggle in the message toolbar sets or clears `\Seen` for that row only and keeps an accessible pressed state. Repeated identical writes are idempotent on the provider.

Unread is derived from cached flags, so an unwritten or failed change simply keeps the prior indicator. The "Unread" view may keep a row visible until the next refresh, consistent with ADR-0033/0042; preserving mounted content takes priority. Rollback removes the UI toggle and automatic call and stops injecting the writer; existing provider flags are untouched and the read-only read path is unchanged.
