# ADR-0028 — Local detached signing foundation

Status: Accepted for local crypto only. No signed-only HTTP submission or visible sending control yet.

The local vault can create a detached OpenPGP signature over a snapshot of MIME entity bytes using its unlocked private key. The selected sender must already be explicitly bound to that fingerprint, with current primary identity and signing-key usability revalidated. Revocation/expiry, changed bindings, lock and epoch changes fail closed. No recipient keys are required for a detached signature. OpenPGP.js performs signing; the fixed SHA-512 policy is checked against the resulting packet before declaring `micalg=pgp-sha512`.

The MIME helper builds multipart/signed around the exact entity bytes without rewriting their headers, transfer encoding or CRLF. It only accepts bounded canonical seven-bit MIME; the existing composer base64-encodes Unicode and attachment octets. Signature armor is the separate second part. The helper is a local formatter, not an authority or cryptographic verifier. Outer From/To/Subject are not authenticated by this entity signature.

Signing provides authenticity/integrity, not confidentiality. This slice introduces no network call, backend plaintext path, model export, draft persistence, reply downgrade or SMTP action. Existing encrypted-parent/plaintext restrictions stay in effect. A future signed-only submission needs its own explicit visible unencrypted-send consent and validated transport boundary; no generic decrypted MIME export is authorized here.

Tests exercise exact byte/attachment preservation, caller mutation during asynchronous signing, sender binding, lock and noncanonical MIME refusal. Actual GnuPG verifies application-produced signatures and rejects mutated signed bytes. Thunderbird acceptance and signed-only sending remain open. No schema/dependency change; rollback is the previous image/source revision.
